## Template variants found while consolidating

Most fields are shared verbatim via YAML anchors across every domain.
Real, confirmed differences, each handled as either a small selector
widening (safe no-op elsewhere) or a dedicated named scraper variant:

- **Title tag**: `<h3>` on most sites, `<h1>` on `blackpayback.com`/
  `radicaljizzlam.com`/`brickyates.com` — `$scene/*[self::h1 or self::h3]`.
- **Tag list label**: "Tags:" on most sites, "Categories:" on
  `femdomempire.com`/`feminized.com` — widened `contains()` check.
- **Date location**: a visible "Date Added:" span on most sites, hidden
  inside an HTML comment on `bathroomcreepers.com` — its own
  `bathroomcreepersSceneScraper` variant.
- **Details paragraph**: an invalid nested `<p><p>` on
  `brandnewamateurs.com` gets HTML5-auto-split into two sibling `<p>`
  elements (the first always empty) — `$scene/p[last()]` fixes this and
  is a safe no-op for the normal single-`<p>` case everywhere else.
- **Image source**: the majority serve `src0_Nx` as relative paths
  (prefixed with `//base/@href`, concat-strip-middle picks the highest
  tier). A few serve `src0_Nx` as already-absolute, **token-signed
  third-party CDN URLs** (`c7620ca2e1.mjedge.net/...?expires=...&token=...`)
  — the documented `CLAUDE.md` CDN-bypass trick applies: swap the CDN
  host for the site's own domain and drop the query string entirely,
  hitting the unprotected origin (also avoids invalidating the signing
  token with the `-full.jpg` suffix swap). `filthyfemdom.com` goes
  further still: its `img.update_thumb` never exists as real DOM at all,
  only as a JS string inside a `<script>` block (same bug class as
  `HotLegsAndFeet.yml`'s original `<video poster>` issue) — its own
  `filthyfemdomSceneScraper` variant extracts from a separate
  `video_content` JS string's plain, unsigned `poster="..."` path instead.
- **`femdomempire.com`'s `performerByURL`**: selectors are correct but
  every `/tour/models/*` page 500s site-side (confirmed via direct
  `curl`) — a live site bug, not a scraper bug.
- **Daily view cap**: this template's shared `js/tour.js` boilerplate
  caps free trailer views per day/session (`maxClicks`/`dayslimit` in the
  page source). Repeated `scrape` calls against the _same_ URL while
  iterating trips it and serves degraded fallback content instead of the
  real page — looks exactly like a flaky selector but isn't. Don't
  re-test one URL repeatedly; use a fresh URL if in doubt.
